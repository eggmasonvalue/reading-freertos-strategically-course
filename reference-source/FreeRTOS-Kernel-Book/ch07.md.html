Reasons for this include:305306- Even if tasks have been assigned a very high priority, they will307  only run if no interrupts are being serviced by the hardware.308309- ISRs can disrupt (add 'jitter' to) both the start time, and the310  execution time, of a task.311312- Depending on the architecture on which FreeRTOS is running, it might313  not be possible to accept any new interrupts, or at least a subset314  of new interrupts, while an ISR is executing.315316- The application writer needs to consider the consequences of, and317  guard against, resources such as variables, peripherals, and memory318  buffers being accessed by a task and an ISR at the same time.319320- Some FreeRTOS ports allow interrupts to nest, but interrupt nesting321  can increase complexity and reduce predictability. The shorter an322  interrupt is, the less likely it is to nest.323324An interrupt service routine must record the cause of the interrupt, and325clear the interrupt. Any other processing necessitated by the interrupt326can often be performed in a task, allowing the interrupt service routine327to exit as quickly as is practical. This is called 'deferred interrupt328processing', because the processing necessitated by the interrupt is329'deferred' from the ISR to a task.330331Deferring interrupt processing to a task also allows the application332writer to prioritize the processing relative to other tasks in the333application, and use all the FreeRTOS API functions.334335If the priority of the task to which interrupt processing is deferred is336above the priority of any other task, then the processing will be337performed immediately, just as if the processing had been performed in338the ISR itself. This section discusses interrupt priorities, which1812are the priorities at which interrupt service routines (ISRs) execute1813relative to each other. The priority assigned to a task is in no way1814related to the priority assigned to an interrupt. Hardware decides when1815an ISR will execute, whereas software decides when a task will execute.1816An ISR executed in response to a hardware interrupt will interrupt a1817task, but a task cannot pre-empt an ISR.18181819Ports that support interrupt nesting require one or both of the1820constants detailed below to be defined in FreeRTOSConfig.h.1821`configMAX_SYSCALL_INTERRUPT_PRIORITY` and1822`configMAX_API_CALL_INTERRUPT_PRIORITY` both define the same property.1823Older FreeRTOS ports use `configMAX_SYSCALL_INTERRUPT_PRIORITY`, and newer1824FreeRTOS ports use `configMAX_API_CALL_INTERRUPT_PRIORITY`.18251826**Constants that control interrupt nesting**18271828- `configMAX_SYSCALL_INTERRUPT_PRIORITY` or `configMAX_API_CALL_INTERRUPT_PRIORITY`18291830  Sets the highest interrupt priority from which interrupt-safe1831  FreeRTOS API functions can be called.18321833- `configKERNEL_INTERRUPT_PRIORITY`18341835  Sets the interrupt priority used by the tick interrupt, and must1836  always be set to the lowest possible interrupt priority.18371838  If the FreeRTOS port in use does not also use the1839  `configMAX_SYSCALL_INTERRUPT_PRIORITY` constant, then any interrupt that1840  uses interrupt-safe FreeRTOS API functions must also execute at the1841  priority defined by `configKERNEL_INTERRUPT_PRIORITY`.18421843Each interrupt source has a numeric priority, and a logical priority:18441845- Numeric priority18461847  The numeric priority is simply the number assigned to the interrupt1848  priority. For example, if an interrupt is assigned a priority of 7,1849  then its numeric priority is 7. Likewise, if an interrupt is assigned1850  a priority of 200, then its numeric priority is 200.18511852- Logical priority18531854  An interrupt's logical priority describes that interrupt's precedence1855  over other interrupts.18561857  If two interrupts of differing priority occur at the same time, then1858  the processor will execute the ISR for whichever of the two interrupts1859  has the higher logical priority before it executes the ISR for1860  whichever of the two interrupts has the lower logical priority.18611862  An interrupt can interrupt (nest with) any interrupt that has a lower1863  logical priority, but an interrupt cannot interrupt (nest with) any1864  interrupt that has an equal or higher logical priority.18651866The relationship between an interrupt's numeric priority and logical1867priority is dependent on the processor architecture; on some processors,1868the higher the numeric priority assigned to an interrupt the *higher*1869that interrupt's logical priority will be, while on other processor1870architectures the higher the numeric priority assigned to an interrupt1871the *lower* that interrupt's logical priority will be.18721873A full interrupt nesting model is created by setting1874`configMAX_SYSCALL_INTERRUPT_PRIORITY` to a higher logical interrupt1875priority than `configKERNEL_INTERRUPT_PRIORITY`.
